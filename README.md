# Rosler Ceiling Fan (Bond Bridge)

로슬러(Rosler) 실링팬을 Bond Bridge를 통해 Home Assistant에서 제어하는 커스텀 통합입니다.

A Home Assistant custom integration that controls Rosler ceiling fans (JH-RM series remotes, about 447.885 MHz) through a Bond Bridge. The documentation is written in Korean.

> [!IMPORTANT]
> 실험적인 통합입니다. 팬 1대와 리모컨 1개(JH52-1, JH-RM2)를 측정한 결과를 바탕으로 만들었으며, 다른 개체에서도 동일하게 동작하는지는 확인되지 않았습니다. 확인된 범위는 [검증 상태](#검증-상태)를 참고해 주십시오.

## 배경

Bond 앱의 리모컨 학습 기능으로는 이 팬을 제어할 수 없습니다. 원인은 다음과 같습니다.

| 원인 | 설명 |
| --- | --- |
| 주파수 | 리모컨의 실제 송신 주파수는 약 447.885MHz(OOK)입니다. Bond Bridge가 이 신호를 깨끗하게 수신하는 지정 주파수 범위는 447.775~448.025MHz이며, 흔히 알려진 447.75MHz는 그 경계에 해당합니다. |
| 카운터 | 리모컨은 버튼을 누를 때마다 신호에 포함된 3비트 카운터(0~7)를 1씩 올려 송신합니다. |
| 수신 규칙 | 팬은 직전에 받아들인 신호와 카운터가 같은 신호를 무시합니다. Bond 앱은 학습한 신호를 그대로 재생하므로, 재생한 신호가 무시됩니다. |

이 통합은 Bond Bridge를 송신기로만 사용하며, 명령마다 카운터를 바꾼 신호를 직접 생성해 송신합니다. Home Assistant의 공식 Bond 통합은 필요하지 않습니다.

## 요구 사항

| 항목 | 조건 | 확인된 환경 |
| --- | --- | --- |
| Bond Bridge | 로컬 API와 로컬 토큰 | BD-1000, 펌웨어 v4.40.1 |
| Home Assistant | 2026.2 이상 | 2026.2.3, 2026.10.4, 2026.11.2 |
| 실링팬과 리모컨 | 로슬러 실링팬 | JH52-1 팬, JH-RM2 리모컨 |

## 설치

### Marketplace (Home Assistant 2026.11 이상)

1. **설정 > Marketplace**로 이동합니다.
2. **Add from link**를 선택하고 **GitHub link**에 `btslaurence/ha-rosler-fan`을 입력한 뒤 **Add**를 누릅니다. 처음 사용하는 경우 GitHub 연결을 한 번 요청합니다.
3. 목록에 추가된 **Rosler Ceiling Fan (Bond Bridge)**를 열어 **Install**을 누르고, 확인 창에서 다시 **Install**을 누릅니다.
4. Home Assistant를 재시작합니다.

### HACS (Home Assistant 2026.10 이하)

1. HACS의 **Custom repositories**에 이 저장소 주소를 추가하고 종류를 **Integration**으로 선택합니다.
2. 통합을 설치한 뒤 Home Assistant를 재시작합니다.

### 수동 설치

1. `custom_components/rosler_fan` 폴더를 Home Assistant의 `config/custom_components/` 아래에 복사합니다.
2. Home Assistant를 재시작합니다.

## 설정

**설정 > 기기 및 서비스 > 통합구성요소 추가**에서 **Rosler**를 검색해 추가합니다.

1. **Bond Bridge 연결:** Bond Bridge의 IP 주소와 로컬 토큰을 입력합니다. 로컬 토큰은 Bond 앱에서 Bond Bridge를 선택한 뒤 Advanced Settings의 Local Token에서 확인할 수 있습니다. IP 주소는 공유기에서 고정해 두는 것을 권장합니다.
2. **리모컨 등록:** 아래 두 가지 방법 중 하나를 선택합니다.
3. **이름 지정:** 팬의 이름을 정하면 장치가 생성됩니다.

| 등록 방법 | 설명 | 확인 상태 |
| --- | --- | --- |
| 값을 직접 입력 | 리모컨 ID(16진수 5자리 또는 2진수 20자리)와 체크섬 상수를 입력합니다. | 실제 Home Assistant와 Bond Bridge에서 등록과 송신을 실행한 방법입니다. |
| 리모컨에서 학습 | 리모컨을 Bond Bridge에서 약 30cm 거리에 두고, 안내에 따라 회전종료 버튼을 화면마다 한 번씩 총 두 번 누릅니다. 통합이 두 신호에서 리모컨 ID와 체크섬 상수를 읽습니다. | 실제 리모컨 신호로는 아직 확인되지 않았습니다. |

### 리모컨 ID와 체크섬 상수

- **리모컨 ID**는 신호의 앞 20비트이며, 리모컨마다 다른 값으로 보입니다.
- **체크섬 상수**는 체크섬 계산에 사용되는 값으로, 개발에 사용한 리모컨에서는 8이었습니다.
- 두 값은 Bond Bridge의 스캔 API(`PUT /v2/signal/scan`, 447885kHz, OOK)로 리모컨 신호를 수신한 뒤 [프로토콜](#프로토콜)에 따라 해석하면 얻을 수 있습니다. 리모컨에서 학습 방법은 이 과정을 자동으로 수행합니다.

> [!WARNING]
> 리모컨 ID와 로컬 토큰은 공개하지 마십시오. 리모컨 ID를 아는 사람은 전파가 닿는 거리에서 팬을 조작할 수 있습니다.

### 설정 변경

- Bond Bridge의 IP 주소나 토큰이 바뀐 경우 통합의 **재구성**에서 수정합니다.
- 송신 주파수(기본값 447885kHz)와 프레임 반복 횟수(기본값 7)는 통합의 **구성**에서 변경할 수 있습니다.
- 팬이 여러 대인 경우 팬마다 통합 항목을 하나씩 추가합니다.

## 제공 기능

팬 한 대가 장치 하나로 등록됩니다.

| 엔티티 | 기능 | 비고 |
| --- | --- | --- |
| 팬 | 켜기, 끄기(회전종료), 속도 6단계, 정방향·역방향, 자연풍 프리셋 | |
| 전체종료 버튼 | 리모컨의 전체종료 | |
| 타이머 버튼 3개 | 1시간, 2시간, 4시간 | |
| 조명 버튼 | 리모컨의 LED 버튼 | 기본적으로 비활성화되어 있습니다. |

진단 정보에서는 리모컨 ID, 토큰, Bond Bridge 주소가 가려집니다.

## 제한 사항

- **상태는 추정값입니다.** 팬은 자신의 상태를 알려 주지 않습니다. Home Assistant는 마지막으로 송신한 명령을 현재 상태로 표시하며, 리모컨으로 변경한 내용은 반영되지 않습니다.
- **타이머는 상태에 반영되지 않습니다.** 타이머로 팬이 꺼져도 Home Assistant에는 켜진 상태로 표시됩니다.
- **리모컨 사용 직후에는 명령이 한 번 무시될 수 있습니다.** 리모컨이 남긴 카운터와 통합이 다음에 사용할 카운터가 우연히 같은 경우이며, 확률은 약 1/8입니다. 명령을 한 번 더 송신하면 동작합니다.
- **지원되지 않는 리모컨이라는 안내가 표시되는 경우**, 리모컨의 신호 방식이 이 통합이 다루는 방식과 다른 것입니다. 화면에 표시되는 두 신호의 값을 [프로토콜](#프로토콜)과 비교해 차이를 확인할 수 있습니다.

## 검증 상태

| 항목 | 상태 |
| --- | --- |
| 주파수, 프레임 구조, 체크섬 식, 카운터 규칙 | 실제 리모컨과 팬으로 측정했습니다(각 1개). |
| 1단, 3단, 회전종료 신호 | 동일한 형식의 신호를 송신해 실제 팬의 동작을 확인했습니다. |
| 통합이 생성하는 신호 | 위 형식과 바이트 단위로 일치함을 자동 테스트로 확인했습니다. |
| 실제 Home Assistant(2026.11.2)와 Bond Bridge | Marketplace 설치, 값 직접 입력 방식의 등록, 송신까지 실행했습니다. 송신한 명령은 1단, 2단, 끄기입니다. |
| 4~6단, 방향, 자연풍, 타이머, 전체종료 | 팬에 송신해 확인하지 않았습니다. 리모컨에서 수신한 코드를 같은 방식으로 생성합니다. |
| 조명 버튼 | 확인하지 않았습니다(조명이 없는 팬에서 개발). |
| 리모컨에서 학습 | 실제 리모컨 신호로는 확인하지 않았습니다. 해석기는 합성 신호로만 시험했습니다. |
| 자동 테스트 | Home Assistant 2026.2.3, 2026.10.4에서 통과했습니다. 2026.11.2에서는 모의 Bond Bridge를 상대로 설정부터 송신까지 실행했습니다. |

## 프로토콜

버튼을 한 번 누르면 33비트 프레임이 7회 송신됩니다. 변조는 OOK이며 비트 하나의 길이는 1ms입니다(0은 250µs 켬 + 750µs 끔, 1은 750µs 켬 + 250µs 끔). 프레임 사이의 간격은 약 7ms입니다.

```
[리모컨 ID 20비트][버튼 4비트][플래그 1비트][카운터 3비트][체크섬 4비트][0]

체크섬 = 버튼 XOR (플래그·카운터 4비트) XOR 상수      (개발에 사용한 리모컨의 상수: 8)
```

| 버튼 | 값 (16진) | 플래그 | | 버튼 | 값 (16진) | 플래그 |
| --- | --- | --- | --- | --- | --- | --- |
| 1단 | 8 | 0 | | LED | 4 | 0 |
| 2단 | 9 | 0 | | 정방향 | 2 | 0 |
| 3단 | E | 0 | | 자연풍 | A | 1 |
| 4단 | 5 | 0 | | 역방향 | 8 | 1 |
| 5단 | 7 | 1 | | 1H | 1 | 0 |
| 6단 | 6 | 0 | | 2H | 4 | 1 |
| 전체종료 | 3 | 0 | | 4H | C | 1 |
| 회전종료 | B | 0 | | | | |

- 카운터는 어떤 버튼이든 누를 때마다 1씩 증가하며, 7 다음에는 0으로 돌아갑니다.
- 팬은 직전에 받아들인 카운터 하나만 기억합니다. 그 값이 아니면 이전에 사용된 카운터라도 받아들입니다.
- 통합은 카운터를 0, 1, 2, 3, 4, 5, 7 순서로 순환해 사용합니다. 6을 건너뛰는 것은 Bond 앱과 함께 사용하는 경우를 위한 것입니다. Bond Bridge에 카운터 2와 6의 두 묶음을 하나의 명령으로 저장해 Bond 앱에서 사용하는 방법이 있는데, 그 명령이 끝나면 팬이 기억하는 카운터가 6이 되기 때문입니다.

## 개발

```
pip install -r requirements_test.txt
pytest
```
